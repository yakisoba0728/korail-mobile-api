# 합격 기준 (최종 감사용)

감사를 **한 번으로 끝내기 위한** 기준입니다. 판정은 이 문서만 기준으로 합니다.
여기에 없는 기대는 결함이 아니라 **새 요구사항**이고, 이번 감사 범위 밖입니다.

## 1. 보장 (위반하면 결함, 반드시 수정)

마스킹 — `redaction.py`

| ID | 보장 |
|---|---|
| G1 | 구조화 입구(`redact_mapping`·`redact_value`·`redact_payload`)는 `is_sensitive_key` 가 참인 키의 값을 **깊이·타입과 무관하게** 전부 가린다. |
| G2 | `redact_url` 은 절대 URL과 `/` 로 시작하는 상대 URL의 민감 쿼리 값과 userinfo 를 가린다. |
| G3 | `redact_text` 에 **문자열 전체가 JSON 문서 하나**인 입력이 오면 구조로 가린다. 출력은 유효한 JSON이고(입력의 NaN/Infinity 리터럴 보존은 예외), 비민감 키·값·순서·중복 키·숫자 리터럴은 그대로다. |
| G4 | `redact_text` 의 자유 텍스트에서 `키=값`·`키: 값`·`"키":"값"` 은, 키가 민감(인덱스 접미사, 키 안의 `%5F`·`\u005f` 포함)하고 값이 **따옴표로 싸였거나 공백 없는 한 토큰**이면 가린다. |
| G5 | 모든 문자열에서 14~19자리 카드번호 모양과 `JSESSIONID=` 값을 가린다. |
| G6 | 어떤 `redact_*` 함수도 `str` 입력에 대해 예외를 내지 않는다. |
| G7 | 등록된 비민감 대조 키(`txtGoHour`·`trnNo1`·`psgNum1_`·`lang` 등)의 독립 `키=값` 을 가리지 않는다. |

파서·클라이언트

| ID | 보장 |
|---|---|
| G8 | 이전에 파싱되던 응답이, 새로 모델링한 선택 필드 때문에 파싱 실패로 바뀌지 않는다. |
| G9 | 변경(mutation) 요청의 응답을 받은 뒤 typed 파싱이 실패하면, 예외의 `.raw` 에 응답 원문이 있다. |
| G10 | `from korail_mobile_api import *` 와 25개 모듈 import 가 성공하고, `__all__` 의 모든 이름이 정의돼 있다. |

## 2. 노력만 함 (알려진 한계 — 결함 아님, 수정하지 않음)

| ID | 한계 |
|---|---|
| L1 | 자유 텍스트에서 따옴표 없는 값에 공백이 있으면 공백 앞까지만 가린다. |
| L2 | 산문에 박힌 JSON에서 민감 값이 **두 겹 이상** 중첩된 배열·객체면 안쪽 괄호에서 끊긴다. |
| L3 | 키의 `_`·`-` 외 문자(영문자 등)까지 escape 된 키는 인식하지 않는다. |
| L4 | `키= ` 처럼 `=` 뒤에 공백이 오면 다음 토큰을 값으로 보고 가린다(이웃 필드가 함께 가려질 수 있음 — 과잉이지 누출 아님). |
| L5 | 예외의 `__cause__`·traceback·비문자열 인자, 모델의 `raw` 는 자동으로 가리지 않는다(호출자가 로깅 경계에서 가림). |
| L6 | `json.loads` 가 거절할 만큼 깊은 JSON은 자유 텍스트 경로로 가서 L1·L2 가 적용된다. |
| L7 | CartInfo 중첩 결제 상세 6객체(String 59개), 보호된 enum·리터럴의 평문, 라이브 캡처 없는 필드의 실제 서버 형식. |

## 3. 문서

주석·독스트링의 7.0.6 관련 사실 주장은 **검증됐거나, 미출처라고 표기돼 있어야** 한다.
어긋나면 문서 결함(D)이다. 동작을 막지 않으므로 일괄 수정한다.

## 4. 판정 분류

감사 결과의 모든 항목은 아래 넷 중 하나로 분류한다.

| 분류 | 뜻 | 처리 |
|---|---|---|
| **C** | 보장(G1~G10) 위반 | 수정. 수정마다 `checks/` 에 회귀 사례 추가 |
| **D** | 문서 결함 | 일괄 수정 |
| **L** | 위 한계(L1~L7)에 해당 | 수정하지 않음 |
| **N** | 기준에 없는 새 기대 | 기록만. 이번 범위 밖 |

## 5. 종료 규칙

1. 감사는 **한 번**이다.
2. C와 D만 고친다. L·N은 고치지 않는다.
3. C를 고친 뒤에는 **전면 재감사를 하지 않는다.** `checks/` 전체 통과와, 고친 C 항목
   각각에 대한 좁은 확인만 한다.
4. 그 확인에서 **새 C가 나오지 않으면 종료**다.

## 6. 실행 가능한 기준

G1~G10 중 기계로 검사할 수 있는 것은 `checks/` 가 검사한다. 종료코드: 0 통과, 1 실패,
2 검사 불완전.

```sh
python3 checks/contract_api.py         # G6·G8·G9·G10
python3 checks/masking_invariants.py   # G1~G7 사례
python3 checks/masking_mutants.py      # 하네스가 비어 있지 않은지
python3 checks/sphinx_symbols.py       # 문서의 파이썬 심볼 참조
python3 checks/decompile_citations.py  # 문서의 디컴파일 인용 (analysis/ 필요)
```

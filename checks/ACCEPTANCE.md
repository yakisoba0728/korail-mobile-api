# 합격 기준

판정은 이 문서를 기준으로 합니다. 2026-09-23 전면 감사(C40·D17·L5·N4)에서 이 문서
자체의 충돌과 빈칸이 D01~D06 으로 지적돼 고쳤습니다. 바뀐 점은 맨 끝 §7 에 있습니다.

## 1. 보장 (위반하면 결함, 반드시 수정)

충돌 규칙: 보장끼리 부딪치면 **가리는 쪽이 이깁니다**(누출보다 과잉 가림).
"민감"은 `is_sensitive_key` 가 참인 키이거나, G5 의 모양(카드번호·세션 값)입니다 —
G5 는 키의 민감성과 무관하게 **값·키·숫자 어디에 있든** 적용됩니다.

마스킹 — `redaction.py`

| ID | 보장 |
|---|---|
| G1 | 구조화 입구(`redact_mapping`·`redact_value`·`redact_payload`)는 민감 키의 값을 **깊이·타입과 무관하게** 전부 가린다. 순환이 아닌 공유 객체는 매번 온전히 처리하고, 깊이 때문에 예외를 내지 않는다(결과의 문자열화 포함). 가린 뒤 키가 겹쳐도 항목을 잃지 않는다. |
| G2 | `redact_url` 은 절대 URL, `/`·`//` 로 시작하는 URL의 민감 쿼리 키(퍼센트 인코딩된 키 포함) 값과 userinfo 를 가린다. 구조 처리가 실패해 되돌아가는 경로에서도 같다. |
| G3 | `redact_text` 에 **문자열 전체가 JSON 문서 하나**인 입력이 오면, **깊이와 무관하게** 구조로 가린다. 출력은 유효한 JSON이고(입력의 NaN/Infinity 리터럴 보존은 예외), 비민감 키·값·순서·중복 키는 그대로이며, 숫자 리터럴은 **바이트 그대로**다 — 단 G5 모양의 숫자는 G5 가 이긴다(`"[REDACTED_CARD]"` 문자열로 바뀐다). |
| G4 | `redact_text` 의 자유 텍스트에서 `키=값`·`키: 값`·`"키":"값"` 은, 키가 민감(인덱스 접미사, 키 안의 `_`·`-` 에 해당하는 `%5F`·`%2D`·`\u005f`·`\u002d` 포함)하면 값을 가린다. 값의 범위: 따옴표 값은 닫는 따옴표까지, `{`·`[` 로 시작하면 **짝이 맞는 닫는 괄호까지(깊이 무관)**, 그 밖에는 **다음 공백까지**(쉼표 포함). 예외는 `&`·`;` 바로 뒤에 `키=` 가 오는 경우로, `=`·`:` 형식 모두 거기서 값이 끝난다(G7). |
| G5 | 모든 문자열 — 값, 매핑·JSON·폼·쿼리의 **키**, URL host, JSON 숫자 리터럴 — 에서 14~19자리 카드번호 모양과 `JSESSIONID=` 값을 가린다. |
| G6 | 어떤 `redact_*` 함수도 `str` 입력에 대해 예외를 내지 않는다. |
| G7 | 등록된 비민감 대조 키(`txtGoHour`·`trnNo1`·`psgNum1_`·`lang` 등)의 독립 `키=값` 을 가리지 않는다. |

파서·클라이언트

| ID | 보장 |
|---|---|
| G8 | 기준 wheel `korail_mobile_api-1.1.1`(로컬 `analysis/reports/7.0.6-additions/dist/`, 감사 묶음에서는 따로 둔 `korail-g8-baseline-1.1.1.whl` 을 `--wheel` 로)이 받아들이던 응답을, 1.1.1 이후 모델링한 필드·중첩 객체 때문에 거절하지 않는다. 비교 대상은 1.1.1 이 `parse_*` 를 정의한 모듈 전부이고, `checks/g8_differential.py` 가 두 버전에 **유한한 생성 입력 행렬**을 넣어 비교한다 — 전칭 증명이 아니라 그 행렬 안에서의 확인이다. 1.1.1 파서가 사라지면 허용 목록(커밋 근거)에 있어야 한다. 1.1.1 에 이미 있던 필드의 입력·반환 정책 변경은 G8 이 아니라 문서(D)로 다룬다. |

| G10 | `from korail_mobile_api import *` 와 모든 하위 모듈 import 가 성공하고, `__all__` 의 모든 이름이 정의돼 있다. |
| G11 | `logout()` 은 서버 호출이 어떻게 실패하든 로컬 세션·쿠키를 비운다. |

## 2. 노력만 함 (알려진 한계 — 결함 아님, 수정하지 않음)

L 은 G 가 **명시적으로 다루지 않는 입력**에만 적용됩니다. G 에 해당하는 입력을 L 로 면제할 수 없습니다.

| ID | 한계 |
|---|---|
| L1 | 자유 텍스트에서 따옴표 없는 값에 공백이 있으면 공백 앞까지만 가린다. |
| L3 | **자유 텍스트에서**, 키의 `_`·`-` 외 문자(영문자 등)까지 escape 된 키는 인식하지 않는다. JSON·URL 파서가 디코딩한 키는 G1~G3 대로 인식한다. |
| L4 | `키= ` 처럼 `=` 뒤에 공백이 오면 다음 토큰을 값으로 보고 가린다(이웃 필드가 함께 가려질 수 있음 — 과잉이지 누출 아님). |
| L5 | 예외의 `__cause__`·traceback·비문자열 인자, 모델의 `raw` 는 자동으로 가리지 않는다(호출자가 로깅 경계에서 가림). |
| L7 | CartInfo 중첩 결제 상세 6객체(String 59개), 보호된 enum·리터럴의 평문, 라이브 캡처 없는 필드의 실제 서버 형식. **G8 의 관대성은 L7 로 면제되지 않는다.** |
| L8 | 자유 텍스트에서 따옴표 없는 민감 값 **안에** `&키=`·`;키=` 모양이 있으면 거기서 값이 끝난 것으로 보고 뒤를 남긴다(G7 의 이웃 필드 보존과 구분할 수 없음). |

(L2·L6 은 삭제했습니다 — G4 의 괄호 짝 규칙과 G3 의 깊이 무관 규칙이 대신합니다.)

## 3. 문서

주석·독스트링의 7.0.6 관련 사실 주장은 **검증됐거나, 미출처·추정이라고 표기돼 있어야** 한다.
선언 위치(`@SerialName`, 필드 선언)는 이름·선언 타입의 근거일 뿐, 실제 서버 응답이나
"항상·유일·전혀" 같은 전칭 주장의 근거가 아니다. 어긋나면 D 이다.

## 4. 판정 분류

| 분류 | 뜻 | 처리 |
|---|---|---|
| **C** | 보장(G1~G11) 위반, **또는** G 에 적히지 않았더라도 실제 동작 버그(크래시, 데이터 손실, 상태 누수), 검사기의 거짓 통과·거짓 실패·비정상 종료 | 수정. 수정마다 `checks/` 에 회귀 사례 |

## 5. 종료 규칙

1. C 와 D 만 고친다. L·N 은 고치지 않는다.
2. 고친 뒤에는 감사가 준 **재현 스크립트를 그대로 다시 돌려** 항목별 결과를 낸다.
3. 그 결과에 대한 확인에서 **새 C 가 나오지 않으면 종료**다.

## 7. 2026-09-23 변경

- D01: "여기 없는 기대는 결함 아님" 삭제. 실제 동작 버그와 검사기 결함도 C.
- D02: 충돌 규칙(가리는 쪽이 이김)과 G5 의 적용 위치(키·host·숫자) 명시.
- D03: G4 값 범위(따옴표·괄호 짝·다음 공백) 명시. L2 삭제.
- D04: G3 을 깊이 무관으로. L6 삭제.
- D05: L3 을 자유 텍스트로 한정.
- D06: G8 기준 아티팩트를 1.1.1 wheel 로 고정하고 새 필드 목록을 기계 추출로.
- 추가: G11(logout 로컬 정리). G9 에 "부분 raw 가 있어도 전체".
- **보장 축소가 둘 있습니다.** 첫째(재감사 ND01 에서 지적): G4 는 예전에 "공백 없는 한 토큰"
  전체를 값으로 봤는데, 개정판은 `&`·`;` 바로 뒤에 `키=` 가 오면 거기서 값을 끝냅니다.
  구현은 예전부터 이렇게 동작했고(G7 의 이웃 키를 지키려고), 문서만 넓게 적혀 있었습니다.
  대가는 실제 누출입니다: 민감 값 **자체에** `&키=` 모양이 들어 있으면
  (`txtPwd=abc&def=ghi` 의 비밀번호가 `abc&def=ghi` 라면) `def=ghi` 가 남습니다. 평문에서
  "값 안의 `&`" 와 "다음 필드" 는 구분할 수 없고, 이웃 필드를 지키는 쪽(G7)을 택했습니다.
  이 경우는 L1 과 같은 성격의 한계로 §2 에 L8 로 적습니다. 나머지는 넓히거나 명확히 한 변경입니다.

## 8. 2026-09-23 재감사 반영

- G4 의 `&`·`;` 경계를 `:` 형식에도 적용(재감사 NC06). **이것이 둘째 보장 축소입니다** —
  예전에는 `txtPwd:SECRET&a=TAIL` 전체를 가렸는데 이제 `a=TAIL` 이 남습니다(최종 검토 지적). L8 에 해당합니다.
- G8 비교 대상을 두 모듈에서 여섯 모듈로 넓히고, 건너뛴 파서는 검사 불완전(2),
  사라진 파서는 허용 목록 없으면 실패(1)(재감사 NC08). 넓히자 limousine·parsers 모듈에서
  G8 회귀 7군이 새로 드러나 고쳤습니다.

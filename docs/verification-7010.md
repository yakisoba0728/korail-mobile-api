# 7.0.10 정적 검토와 변경 범위

2026-10-19 코레일+ 안드로이드 앱 7.0.10과 SDK를 정적으로 대조한 결과의 공개 요약입니다.
공개 메서드 **85개를 각각 한 행씩 검토**했지만, 보호된 값·전체 분기·최종 wire 요청을 모두 확인한 것은 아닙니다.
앱 실행이나 실서버 요청, 실제 예약·결제·환불은 하지 않았습니다. 이 검토는 7.0.10 실서버 호환 인증이 아닙니다.

## 버전 구분

이 검토의 변경 사항은 이후 패키지 2.6.0에 포함합니다. 아래 버전·배포 상태는 **정적 검토 당시의 기록**이며,
당시의 관측을 2.6.0 배포본 자체의 실서버 검증으로 바꾸지 않습니다.

| 구분 | 정적 검토 당시 개발 변경 |
|---|---|
| 오류 메시지 사전 | 앱 7.0.10 기준, 일반 결과 코드 10,305개·메시지 17,256개 |
| 요청 기본 `AppVersion` | `7.0.8` 유지. `KorailConfig(app_version="7.0.10")` 명시 가능 |
| API `Version` | 기존 값 유지. 앱 버전과 별개 |
| 패키지 버전 | `2.5.0` 유지. 변경 이력은 Unreleased |
| 태그·배포 | 이 작업에서 생성·실행하지 않음 |

사전 차이는 `WRD000058` 한국어 안내의 1개월→2개월입니다. 영어는 그대로 보존합니다.
메시지를 근거로 날짜 제한·오류 분류를 변경하거나, 사전 버전을 요청 버전으로 간주하지 않습니다.

## 반영하는 계약

### 요청 순서

- 은행 조회의 직접 `@Field` 경로는 `Device, Version, Key, AppVersion` 순서입니다. 빈 `Key`,
  `AppVersion=None` 생략, `lang` 미전송 규칙은 유지합니다.
- 환불과 환불 수수료 조회는 상위 공통 필드를 먼저 직렬화합니다. 생성자의 인자 나열 순서와
  직렬화 순서를 구별합니다.
- 이는 확인한 앱 근거와의 정합성 수정입니다. 보호된 최종 map·서버의 순서 민감성·실서버 영향은 미확인입니다.

### 환불 대상 연결 — fail-closed 변경

`get_refund_commission`이 반환하는 응답에 조회 당시의 원표 식별자·동반자 정보를 비공개 문맥으로 연결합니다.
`refund`는 성공 응답인지 확인하고 다음 값이 환불 입력과 일치해야 요청합니다.

- 원표 창구번호, 원표 반환일, 일련번호, 반환 비밀번호
- 동반자 이름, 증빙번호(상세의 동반자 생년월일)

직접 생성·직접 파싱한 수수료 응답, 다른 승차권의 응답, 원표 반환일이 없는 `PaidTicket`은 요청 전에 거절합니다.
성공 봉투만 수동으로 채우던 호출 방식은 더 이상 허용되지 않습니다. 수수료 자동 조회나 환불 자동 재시도는 없습니다.

`PaidTicket`의 새 키워드 전용 필드는 `return_sale_date: str | None = None`,
`companion_name: str = ""`, `companion_certificate_no: str = ""`입니다.
`from_refund_detail()`은 상세의 `original_sale_date`를 원표 반환일로, 동반자 이름·생년월일을 동반자 필드로 복사합니다.
현재 판매일인 `sale_date`는 별도로 유지합니다. 수동 생성 시 원표 반환일을 명시해야 합니다.
기존 `get_refund_commission` 시그니처는 그대로이며,
간편 API는 `TicketResource.refund_fee(ticket, *, companion=RefundCompanion())`로 동반자 정보를 받습니다.

조회 문맥과 새 필드는 `repr`에서 숨기고 개인정보를 파일로 저장하지 않습니다.
직접 속성 접근·`raw`·일반 dataclass 직렬화 전체를 마스킹하는 기능은 아닙니다.
이 연결은 대상 혼용을 막는 로컬 검증일 뿐, 수수료 금액의 유효기간·서버 승인·임의 변조 방지를 보장하지 않습니다.
조회 입력에 없는 PNR·현재 판매일·재발행 세대까지 연결하는 검사는 아닙니다.
실제 사용 순서는 [환불 가이드](guide/payments.md#commission)를 참고하세요.

### 좌석배정 조회의 기존 확장

`seatAttCdN/psgNumN/stlbDturDvNmN`의 `*2` 이상 번호 그룹은 앱 DTO에서 확인한 단일 묶음과 다른 SDK 확장입니다.
기존 1~9명 입력과 폼 생성은 유지하며, 여러 명을 한 명으로 무음 축소하지 않습니다.
과거 열차 목록·거절 코드 관측은 보존하지만 그것으로 모든 번호 그룹의 서버 의미를 확정하지 않습니다.

## 미확정 — 임의로 바꾸지 않는 부분

| 항목 | 남은 확인 사항과 정책 |

| 통합결제 | 통합결제와 기존 결제 선언이 공존합니다. 일반 회원·단일 PNR·국내카드 분기를 확인하기 전 endpoint 교체·교차 재시도를 하지 않습니다. |
| 서비스 상태 | CommonIn 상속만으로 기본값이 실제 전송된다고 단정하지 않습니다. `encodeDefaults`와 emitted map이 미확정이므로 필드를 임의 추가하지 않습니다. |
| N카드·보호 기본값 | 성공 분기·직렬화 근거가 부족한 부분을 호환 완료로 바꾸거나 값을 추측하지 않습니다. |

Android push ACK, 비회원 UI 경고, 열차 선택 안내, 진단 화면은 회원용 Python SDK에 이식하지 않습니다.
0원·예약대기(STANDBY) 홀드 카드 결제 차단, 보수적 금액 검증, 원문 보존, 변경 요청 재전송 금지는 유지합니다.

## 2026-10-23 기본 2! 진단 {#diagnostic-20261023}

Unreleased의 기본 클라이언트와 profile/env 설정을 SDK 2.0.1 native-unavailable 진단으로 전환합니다.
요청 버전·전송/오류 정책·대기열·공개 시그니처는 `main`의 기존 동작을 유지합니다.
기본 헤더는 다음과 같고, 기본 토큰에 기기값을 합성하지 않습니다.

```text
2!v=2&es=165489088780120535&st=Android&sv=2.0.1&ai=korailplus
```

정적 근거는 7.0.10 APK SHA-256 `2847ceb54ba7f7e26edf3426ed606bb1f7e7dfabacf01011d6d164eb45dc993b`의
`J0.java:233–273`/`J0.smali:1917`에 있는 `2!` 직렬화와 `J0.java:303–307`의 native-unavailable 코드입니다.
profile/env로 제공한 OS·모델·기기 식별자는 UTF-8의 padding 없는 Base64url로 `os`·`dm`·`iid` 순서에 넣습니다.
명시적 v1 `token_settings`·외부 공급자와 기존 경로 allowlist·명시적 헤더 생략·필수 토큰·무재시도 계약은 유지합니다.
기본 설정의 pickle 복원도 검사합니다. env builder는 v1 전용 `KORAIL_DYNAPATH_AS_VALUE`를 더 이상 읽지 않습니다.

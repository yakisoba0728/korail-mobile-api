# 03. 로그인/계정/NFilter 정적 심층 분석

분석 범위는 `korail.apk`의 로컬 정적 산출물(`analysis/jadx/sources`)과 기존 정적 요약 문서이며, 운영 API 호출은 수행하지 않았다. 이 APK의 기본 API/Web host는 `S4.z.getSSLHost()` 기준 `https://smart.letskorail.com`이다. [source: `analysis/jadx/sources/S4/z.java:46`, `docs/korail-apk-analysis.md:1`]

## 20-agent follow-up audit 보강

- `LoginDao.executeDao()`의 cookie copy는 login API 응답 직후 수행되며, UI success 판정 이전에도 실행된다. 반면 로컬 로그인 저장은 이후 `S4.u.isLoginSuccess()` 계열 성공 판정에 의해 gating된다.
- `pwdAESCphd=Y` branch는 단순 AES 전송이 아니라 `Base64(AES/CBC(...))` 결과를 다시 outer Base64로 감싼 형태다. `pwdAESCphd`가 아니면 raw password를 single Base64로 보낸다.
- 자동 로그인은 타입별로 갈린다. easy-login type은 `BaseActivity.G()`가 복호화한 `KEY_LOGIN_ID`를 `custId`로 보내며 password/idx를 쓰지 않는다. 일반 자동 로그인은 복호화한 `KEY_LOGIN_PW`와 `LOGIN_DATA.idx`를 사용한다.
- easy-login success는 ID/custNo를 저장하지만 `KEY_LOGIN_PW`를 새로 쓰거나 지우지 않는다. `KEY_AUTO_LOGIN=true`인 상태에서 `DataActivity`가 복호화된 `KEY_LOGIN_PW`를 포함할 수 있으므로 stale encrypted password risk가 남는다.
- AnyID WebView 비회원 flow는 `VAR_DATA.anyid=Y`로 열리고, result type `32`가 비회원 이름/전화번호와 빈 password를 세팅한 뒤 비회원 로그인 성공으로 돌아온다.
- logout cleanup의 실제 범위는 cookie 제거, `KEY_AUTO_LOGIN=false`, `KEY_LOGIN_PW=""`다. `KEY_LOGIN_ID`, `KEY_LOGIN_TYPE`, `KEY_LOGIN_CUST_NO`, integration prefs는 명시적으로 지우지 않는다.

# 7.0.6 APK에서 빠진 호출 정리

7.0.6의 Retrofit 메서드 전수 목록과 기존 Python 전송 허용 목록을 비교했다. 아래의 다섯 경로는 새 APK의 Retrofit 선언에서 찾지 못했다. 이는 **새 앱의 기본 호출 계약에서 제외되었다는 정적 근거**이며, 기존 서버 경로가 폐기되었다는 증거는 아니다. Retrofit 이외의 호출이나 서버의 과거 경로 호환 여부는 확인되지 않았다.

| 기존 호출 | 7.0.6 기준 처리 | Python 공개 API |
| --- | --- | --- |
| `POST /classes/com.korail.mobile.myTicket.MyTicketList` | `MyTicketNewList.do`로 이전 | `get_ticket_list()` 유지, 새 경로 호출 |
| `GET /file/CACHE/prdMobilePlusNotice.cache` | 별도 캐시 호출 제거. `prdMobilePlusMain.cache` 응답의 `notice` 객체 사용 | `get_notice()` 유지, 메인 캐시 POST |
| `POST /classes/com.korail.mobile.gift.gdLst.do` | 대체 조회 경로가 확인되지 않아 전송 허용 목록에서 제거 | `get_gift_ticket_list()` 제거 |
| `POST /classes/com.korail.mobile.seatMovie.LimousineScheduleView` | 대체 조회 경로가 확인되지 않아 전송 허용 목록에서 제거 | `get_limousine_schedule_view()` 제거 |
| `POST /classes/com.korail.mobile.tk.plfNo.do` | 같은 의미의 직접 조회 경로가 확인되지 않아 전송 허용 목록에서 제거 | `get_platform_numbers()` 제거 |

기프티켓·리무진 연계 스케줄·플랫폼 번호의 과거 요청 모델, 폼 빌더, 응답 파서는 저장된 6.5.0 자료를 해석할 수 있도록 남겨 두었다. 현재 클라이언트는 이 세 경로를 전송하지 않는다. 7.0.6 승차권·스케줄 응답에 플랫폼 정보가 있더라도, 이를 과거 `plfNo.do` 호출과 동일한 결과로 취급하지 않는다.

정적 비교 근거: [route-surface.md](../analysis/reports/7.0.6-compare/route-surface.md), [7.0.6 Retrofit 메서드 목록](../analysis/reports/7.0.6-review/network-inventory.md). 새 계약에 대한 라이브 서버 검증은 아직 없다.

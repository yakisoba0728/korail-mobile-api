# 요청 흐름

이 페이지는 메서드 하나를 호출했을 때 라이브러리 안에서 일어나는 일을 순서대로 설명합니다.
각 단계는 코레일+ 안드로이드 앱 7.0.6의 동작을 기준으로 합니다.

![요청 흐름](../assets/flow-light.svg#only-light)
![요청 흐름](../assets/flow-dark.svg#only-dark)

## 1. 요청 만들기

메서드에 넘긴 값은 앱이 쓰는 요청 형식(폼)으로 바뀝니다.

- **필드 순서**: 앱은 요청 객체(DTO)에 선언된 순서대로 필드를 보냅니다. 라이브러리도 같은 순서로 폼을 만듭니다.
  목록 값은 `txtSeatNo1`, `txtSeatNo2`처럼 1부터 번호를 붙입니다.
- **공통 필드**: 대부분의 요청은 맨 앞에 `Device`, `Version`, `Key`를 싣습니다. 환불과 환불 수수료 조회만 앱처럼 공통 필드를 맨 뒤에 둡니다.
- **언어**: `KorailConfig.lang`을 설정하면 `Key` 다음에 `lang`을 보냅니다. 설정하지 않으면 보내지 않습니다.
- **빈 값**: 값이 빈 문자열인 필드는 보내지 않습니다. 운임 조회의 상품번호처럼 앱이 빈 값을 그대로 보내는 필드는 예외로 보냅니다.
- **입력 검사**: 카드번호 자릿수, 승객 수, 환승 구간 순서처럼 앱이 화면에서 막는 입력은 요청을 보내기 전에 검사하고 `KorailProtocolError`를 발생시킵니다.

## 2. 대기열 통과

열차 조회, 예약, 결제, 예약 내역 조회는 요청 전에 NetFunnel 대기열을 거칩니다. 앱과 같은 순서로 진행합니다.

1. 대기열 서버에 입장 키를 요청합니다(`5101`).
2. 대기가 필요하다는 응답(`201`, `202`)이면 서버가 알려 준 시간만큼 기다린 뒤 다시 확인합니다(`5002`). 대기 시간은 1~30초로 제한합니다.
3. 통과하면 KORAIL API에 요청을 보냅니다.
4. 요청이 끝나면 성공·실패와 관계없이 입장 키를 반납합니다(`5004`).

관문은 두 종류입니다.

| 관문 | 쓰는 곳 | 대기열 서버 오류 시 |
|---|---|---|
| `inquiry`, `peak_season_inquiry`, `product_inquiry` | 열차 조회 | 대기열을 건너뛰고 요청을 보냅니다. |
| `reserve`, `pay`, `reservation_view` | 예약, 결제, 예약 내역 조회 | 요청을 보내지 않고 예외를 발생시킵니다. |

대기열 서버가 요청을 차단하면(`301`, `302`) `KorailQueueRejectedError`가 발생합니다.
입장 키는 대기열 서버와만 주고받으며 KORAIL API 요청에는 싣지 않습니다.
대기열 설정은 [설정](../guide/configuration.md)을 참고하세요.

## 3. 전송

- **헤더**: API 요청은 앱과 같은 `User-Agent: korailtalk`에 `Connection: Keep-Alive`, `Accept-Encoding: gzip`을 보내고 `Accept`는 보내지 않습니다.
  대기열 요청은 앱의 대기열 SDK처럼 안드로이드 기본 User-Agent(`Dalvik/2.1.0 (...)`)를 사용하며, 본문이 빈 POST로 보냅니다.
- **DynaPath**: 로그인, 열차 조회, 운임 조회, 예약처럼 앱이 보호하는 경로에는 DynaPath 토큰 헤더를 붙입니다. 기본값으로 켜져 있습니다.
- **로그인 비밀번호**: 서버에서 받은 암호화 정보로 AES 암호화한 뒤 보냅니다. 암호화 정보가 없으면 평문으로 보내지 않고 거절합니다.

## 4. 응답 판정

KORAIL 응답에는 공통 상태 필드(이 문서에서는 **봉투**라고 부릅니다)가 있습니다.

| 필드 | 뜻 |
|---|---|
| `strResult` | `SUCC` 또는 `FAIL` |
| `h_msg_cd` | 결과 코드 (예: `IRZ000001`) |
| `h_msg_txt` | 결과 메시지 |

- `strResult`가 `FAIL`이면 실패입니다. 결과 코드에 따라 [`KorailAppError`][korail_mobile_api.errors.KorailAppError]의 하위 예외(예: 매진, 결과 없음)를 발생시킵니다.
- 실패 코드가 `P058`이면 세션 만료로 보고 [`KorailSessionExpiredError`][korail_mobile_api.errors.KorailSessionExpiredError]를 발생시키며, 로컬 세션을 비웁니다.
- 카드 결제처럼 실패도 정상 응답으로 돌려줘야 하는 메서드는 예외 대신 `str_result`가 `FAIL`인 응답 모델을 반환합니다. 각 메서드 설명에 표시했습니다.

## 5. 응답 읽기

응답은 메서드마다 정해진 dataclass로 바뀝니다. 읽는 규칙은 모든 메서드에 공통입니다.

- **정수와 문자열**: 앱이 문자열로 선언한 필드를 서버가 JSON 정수로 보내는 경우가 있습니다(예: `"0001"` 대신 `1`). 이런 값은 문자열로 바꿔 담습니다. `true`/`false`는 정수로 취급하지 않습니다.
- **선택 필드**: 응답에 없거나 `null`이거나 타입이 맞지 않는 선택 필드는 `None`입니다.
- **필수 필드**: 다음 요청에 다시 보내야 하는 값(예약 번호, 반환 식별자 등)이 없거나 타입이 틀리면 [`KorailProtocolError`][korail_mobile_api.errors.KorailProtocolError]를 발생시킵니다.
- **원본 보존**: 모든 응답 모델의 `raw`에 서버가 보낸 원본이 그대로 남습니다.

### 앱 기본값을 쓰는 필드

아래 18개 필드는 응답에서 빠지면 `None` 대신 앱과 같은 기본값을 씁니다. 문자열은 `""`, 숫자로 바꾸는 필드는 `None`입니다.

| 위치 | 필드 | 개수 |
|---|---|---:|
| 역 목록 | `stn_cd`, `stn_nm` | 2 |
| 호차·좌석 속성 | `h_srcar_no`, `h_rest_seat_cnt`, `h_psrm_cl_nm`, `seatAttNm` | 4 |
| 좌석 배치 | `layout_type`, `seat_ary_cd` | 2 |
| 좌석 | `seat_no`, `sale_psb_flg`, `dir_seat_att_cd`, `rq_seat_att_cd`, `seat_spec`, `sqr_no`, `intg_msg_cd`, `intg_msg` | 8 |
| 창문 위치 | `st_loc_rt`, `cls_loc_rt` | 2 |

## 6. 실패했을 때

- 응답을 읽지 못하면 [`KorailProtocolError`][korail_mobile_api.errors.KorailProtocolError] 등의 예외를 발생시킵니다.
  예외의 `raw`에는 서버가 보낸 응답 전체가, `parser_raw`에는 읽다가 멈춘 부분이 들어 있습니다.
- 예약·결제·환불 같은 변경 요청은 자동으로 다시 보내지 않습니다. 응답을 읽지 못했어도 서버에서는 이미 처리됐을 수 있기 때문입니다.
  이때는 예외의 `raw`나 `get_reservation_history()`로 먼저 결과를 확인하세요.

## 확인되지 않은 부분

앱 내부의 일부 값은 공개돼 있지 않아 라이브러리가 확인하지 못했습니다. 이런 부분은 실서버에서 통한 값을 쓰며, 해당 메서드 설명에 표시했습니다.

- 대기열 관문 식별값과 일부 관문의 사용 조건(성수기 조회, 특가 상품 조회)
- DynaPath 차단 응답을 판정하는 정확한 기준
- 일부 할인·환불 제어값

메서드별 실서버 확인 여부는 [실서버 확인 현황](../status.md)에 있습니다.

# KORAIL Talk 7.0.6 APK ↔ 현재 코드 1:1 정적 대조

> 이 문서는 2026-09-15 구현 전 작업 트리의 읽기 전용 감사 기록이다.
> 이후 구현과 현재 남은 차이는 [7.0.6 구현 후속 결과](7.0.6-implementation-followup.md)를 참조한다.
> 1.2.0 슬림다운은 이 문서가 당연하게 전제하는 것들 — 메서드별 동의 게이트, 117행 V7
> 계약 등록부(지금은 `verifyOnlineRefunds`·`executeOnlineRefunds` 두 개), `android_features.py`
> — 를 코드에서 들어냈다. 아래 `android_features.py`·`v7_contract_data.py`·
> `tests/test_v7_additions.py`로의 줄 번호 링크는 이 문서가 쓰인 시점의 트리를 가리키며,
> 그중 여러 개는 더 이상 존재하지 않는다.

2026-09-15 현재 **작업 트리**와 `analysis/apktool`, `analysis/jadx`의 7.0.6 디컴파일 결과를 대조했다. 8개 에이전트가 인증·전송, 검색·좌석, 예약·변경, 결제·환불, 승차권·부가서비스, 계정·패스, Retrofit 전수 선언, Android 내부 상태를 각각 읽기 전용으로 확인했다. 이 문서는 **정적 계약과 화면 흐름**의 판정이다. 이번 감사에서 실서버 요청이나 결제·예약을 수행하지 않았으며, 현재 코드도 수정하지 않았다. 서드파티 라이브러리의 모든 DEX 클래스와 Python의 클래스별 동일성은 이 클라이언트의 기능 범위에 속하지 않는다.

## 전체 판정

| 기준 | 결과 | 의미 |
| --- | ---: | --- |
| APK Retrofit 메서드 | 185개 / 10개 인터페이스 | [`api-endpoints.tsv`](../analysis/reports/api-endpoints.tsv)에 전수 색인 |
| APK 고유 HTTP 동사·경로 쌍 | 177개 | 현재 고수준 허용 경로 65쌍 + V7 등록 경로 112쌍 = **177/177 대응** |
| 신규 V7 메서드 선언 | **117/117 일치** | 인터페이스·메서드명·동사·경로·입력 주석 순서·폼 여부·응답 DTO 일치; [`v7_contract_data.py`](../src/korail_mobile_api/v7_contract_data.py) |
| 나머지 APK 메서드 | 68개 / 65쌍 | 세 쌍은 오버로드라 경로 목록에서 메서드 차이가 숨는다. 아래의 QueryMap, 승차권별 MAAS, Push 별도 호스트는 선언/사용 방식이 다름 |
| 화면·입력·응답·Android 동작 | **1:1 불일치** | 경로 등록만으로 APK의 분기·필드 값·파서·로컬 상태 전이를 구현했다고 볼 수 없음 |

이전 [`route-surface.md`](../analysis/reports/7.0.6-compare/route-surface.md)는 수정 전 허용 목록을 분석한 당시의 수치(69/177)를 담고 있어 현재 작업 트리의 177/177 판정에 적용하지 않는다. 모든 제휴 호스트의 실제 값과 보호된 문자열의 동등성은 별도 미판정이다.

## 경로는 있으나 업무 흐름은 원시 게이트웨이 수준

V7 등록부는 제휴 조회 23개, Push, 위젯, 선물 송신·회수, MAAS 취소, 좌석 변경·여정 변경, 통합 정산, 지연보상 신청, 현금 반환, 계정 탈퇴, 패스/KR Pass 발권·결제·변경, 마일리지 적립, Railplus 충전, XPoint/OkCashbag 인증의 Retrofit 선언을 옮겼다. [`V7Gateway`](../src/korail_mobile_api/v7.py#L249)는 메서드별 전송 동의 장벽과 원시 응답을 제공하지만, APK 화면의 입력 DTO별 스키마·선택값 연결·결과 처리·Android 실행체를 모두 재현하지 않는다. 특히 상품 취소처럼 경로가 맞아도 DTO에 없는 키를 gateway가 받아들이는 곳이 있다. API 표면 대응과 완성된 사용자 기능을 구분해야 한다.

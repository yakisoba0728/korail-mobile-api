# 7.0.6 추가 기능 구현

7.0.6 APK의 Retrofit 주석에서 확인한 기존 허용 목록 밖의 고유 메서드 117개를
`KorailClient.v7.call()`로 연결한다. 경로/HTTP 동사 고유 쌍은 112개다. 같은 경로를
여러 메서드가 공유해도 메서드 이름, 어노테이션 입력형, 응답 모델명을 각각 보존한다.
원본과 대조 가능한 전체 목록은
`src/korail_mobile_api/v7_contract_data.py`, 생성 근거는
`analysis/reports/7.0.6-additions/methods.tsv`와
`analysis/reports/7.0.6-additions/input-models.tsv`다.

| 경계 | 메서드 | 조회로 분류 | 동의가 필요한 상태 변경 |
| --- | ---: | ---: | ---: |
| KORAIL `NetworkApi` | 92 | 28 | 64 |
| 제휴 API 8개·별도 `PushService` | 25 | 24 | 1 |
| 합계 | **117** | **52** | **65** |

`GET product.ReservationCancel`과 `GET PushService.push.update`처럼 GET이지만
취소·갱신에 해당하는 계약은 상태 변경으로 다룬다. 분명히 조회 또는 서버 쪽
변환으로 확인된 메서드만 조회로 분류했고, 불확실한 경우에는 메서드별 동의를
요구한다. dry-run 미리보기는 원시 wire key의 의미가 보호돼 있을 수 있어
값을 모두 가리고 키 이름과 반복 개수만 보여준다. 메인 KORAIL 호출은 기존
`KorailHttpClient`의 세션 쿠키와 DynaPath
설정을 사용한다. 제휴 API는 호출자가 각 인터페이스의 HTTPS origin을 주입해야
하며, 인터페이스별 독립 클라이언트를 만들되 APK의 공유 CookieManager처럼 메인
클라이언트와 도메인 범위의 쿠키 저장소를 공유한다. `PushService`는 보호된
webHost origin을 호출자가 주입하되 APK처럼 메인 HTTP 클라이언트를 공유한다.

현재 코드는 생성 데이터에서 조회로 표시된 `NetworkApi` 11개를 상태 변경 가능
계약으로 보수적으로 재분류한다. 비밀번호·포인트 인증 5개(`postDiscountCheck`,
`postInquiryIsMember`, `postLPotAthn`, `postXPointView`,
`postOkCashbagCertView`), 체크인·QR·회원 인증·결제 상태 확인 5개
(`postSelfCheckInInfo`, `postSelfCheckInPossible`,
`postLocalRailwayTravelQrAuth`, `postMemberVerify`, `paymentMassStatusIn`),
비회원 예약을 만드는 `postNonMemTicket`(응답 `ReservationOut`) 1개다. 이 11개는
`v7_contract_data.py`의 Retrofit 서명은 유지하고 실행 경계에서 메서드별 동의와
기본 dry-run을 요구한다. 서버에는 전송하지 않았다.

```python
from korail_mobile_api import KorailClient
from korail_mobile_api.v7 import V7MutationConsent

client = KorailClient()
metadata = client.v7.call("NetworkApi.getSearchMetaData", {"version": "7"})

# 정확한 메서드만 허용하며 기본값은 dry-run이다.
consent = V7MutationConsent(
    allow_methods=frozenset({"NetworkApi.productCancel"})
)
preview = client.v7.call(
    "NetworkApi.productCancel",
    {"txtVrRsNo": "sample-reservation-no", "txtGdSqno": "sample-product-seq"},
    consent=consent,
)
client.close()
```

폼의 반복 `@Field`는 문자열 목록으로 전달한다. Retrofit nullable 인자는
해당 키를 생략한다. `@FieldMap`과 `@QueryMap`은
APK DTO의 Python 속성명이 아니라 실제 wire key를 받는다. `@Body`는 JSON
object, `@Header`는 `headers=`로 별도 전달한다. `GreenCarDetailRequest`는
문자열 필드 2개, `CacheCheckRequest`는 문자열 맵 1개를 요구한다. DTO가 상속하는
`Device`/`Version`/`Key`를 포함해야 하는 계약에서는 `include_common=True`를
선택할 수 있다. APK의 보호 코드에 숨은 `lang`, Key/Version 새 기본값,
일부 직렬화 필드 이름은 임의로 채우지 않는다.

Android 내부의 자동 로그인, PIN, 생체인증, 로컬 레코드, 푸시 흐름은
`korail_mobile_api.android_features.AndroidFeatures`가 연결한다. 일반 로그인
자격증명은 호스트의 KeyStore 암호화로 저장하고, 자동 로그인은 저장된 `auto`
설정과 `inputFlag`를 재사용한다. 회원 로그인은 현재 고객번호가 일치해야 하며
`LoginType.NONE`은 이 검사를 건너뛴다. PIN은 6자리 숫자로 로컬 비교하며 오류
5회에서 잠기고 PIN 또는 생체 로그인 성공 시 오류 수를 초기화한다. 생체
자격증명은 BiometricPrompt에 묶인
호스트 키로 별도 봉인/해제한다. 로컬 기록은 APK Room의 18개 DAO 이름으로
분리하며, Preferences DataStore 2개와 메모리 DataStore 8개도 별도 namespace로
접근한다. 소셜 로그인 기록은 암호화 고객 ID와 로그인 수단 코드를 저장한다.
푸시 설정은 Android SmartAgent/FCM 호스트 어댑터와 새
`NetworkApi.postPushUpdate`/`PushService.pushUpdate` 계약으로 이어진다.
로그아웃은 서버 로그아웃을 호출하면서 저장 ID 설정을 유지하거나 지우고,
저장 비밀번호·자동 로그인 설정을 해제한다. 위젯과 고객 여행기록은 전체 행을
삭제하고 Push off로 바꾼다. 간편/소셜 로그인과 승차권 로컬 기록은 유지한다.

이 저장소는 Python 클라이언트여서 Android KeyStore, Room, BiometricPrompt,
FCM/SmartAgent 실행체는 담지 않는다. `AndroidRecordStore`,
`AndroidCredentialCipher`, `AndroidBiometricGate`, `AndroidPushAdapter`의
호스트 구현을 주입해야 실제 단말 기능이 실행된다. 보호된 제휴사 호스트와
인증 헤더도 실행 환경에서 제공해야 한다. 이번 구현은 정적 APK 계약의 호출
형태와 로컬 상태 흐름을 다룬다. Python 클라이언트의 실서버 로그인·조회·미결제
예약 및 취소 결과는 [7.0.6 실서버 검증](7.0.6-live-verification.md)에 기록했다.
이후 일반 승차권의 실카드 결제·전액 환불 한 건은 Python 클라이언트로
실서버에서 성공했다. 신규 V7 변경 계약과 Android 내부 호스트 실행은
실서버·단말에서 검증하지 않았다.
